Tube School

An eight-lesson robotics playground: move a simulated robot arm, record an assisted example, fit a small imitation model, and test what happens when the scene changes.

MuJoCoWorked examplesEmbedded assessment
Launch simulation ↗Source & guide ↗
Design notes & limitations
Learning purpose
Make robotic control, demonstration, model fitting, and generalization available for novice investigation without requiring a physical robot.
Design response
Each lesson combines a goal, worked example, learner action, optional hint, and question with feedback. Controlled changes encourage prediction and explanation.
Project context
An independent educational project drawing on a publicly documented robotics workspace idea. The repository credits NVIDIA’s inspiration, Google DeepMind’s MuJoCo Menagerie robot assets, MuJoCo, and Three.js; it is not an endorsed NVIDIA product.
Important boundary
The model fits joint-command trajectories in a fixed layout. It is not reinforcement learning, a vision policy, or a real-robot deployment. Browser tests establish implementation behavior, not educational effectiveness.

ML Explorer

A modular introduction to data labeling, classification, data quality, bias, and model evaluation, using browser-based activities for elementary learners.

Simulated MLFormative checksReflection

Design notes & implementation
Learning purpose
Break unfamiliar machine-learning ideas into small, inspectable activities with opportunities to check and explain understanding.
Design response
A recurring sequence moves from goals and examples through a pre-check, activity, feedback, and self-reflection. Progress is stored in the browser.
Implementation
The repository describes six self-contained modules using simulated outcomes rather than deployed machine-learning models. The project is distinct from the collaborative Compose and Code platform.
Evidence & next questions
Code and documentation show the instructional sequence. Learner usability and conceptual understanding still require empirical evaluation; simulations should not be interpreted as performance benchmarks.

02 / Design approach

Start with learning.
Build with purpose.

My approach connects the learner, the learning goal, the design, and the evidence needed to improve it.

01 / UNDERSTAND

Begin with people.

Identify learners’ goals, existing knowledge, language, resources, and the setting in which a tool will be used.

02 / DESIGN

Make thinking visible.

Use worked examples, graphic organizers, guided questions, and manageable steps that invite explanation.

03 / DEVELOP

Create and revise.

Connect prototypes with instructional goals. Consider navigation, readable language, learner control, and different ways to participate.

04 / EVALUATE

Ask what was learned.

Separate usability and engagement from understanding. Use feedback, learners’ work, and appropriate research methods to guide revisions.

05 / About my work

Computing educator.

I am an Assistant Professor at The University of Texas at Arlington, with appointments in the College of Education and the Division of Data Science in the College of Science. My work connects computing and STEM education, AI literacy, educational robotics, and educator preparation.

I am interested in how people learn computational ideas—and how thoughtful design can help them create, test, explain, and revise. This portfolio brings together collaborative research resources and smaller development projects that make those interests tangible.
